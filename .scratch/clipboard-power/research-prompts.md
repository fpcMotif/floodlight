# Clipboard Power — web research prompts

Paste each block into a research-mode chat (Fable 5.1 web, ChatGPT Pro, or similar).
Each prompt is self-contained. "Bring back" says what to paste back into the spec issue
or the implementing agent's context. Prompts are ordered by how much they de-risk.

Context line to prepend to every prompt:

> I am building a keyboard-first Spotlight replacement for macOS 14+ in Swift 6.4 / SwiftUI
> (no third-party dependencies, strict concurrency, privacy-first, nothing leaves the Mac).
> It has a Clipboard History mode with a two-column list + inspector. Answer with primary
> sources (Apple docs, WWDC sessions, open-source clipboard managers on GitHub), cite them,
> and flag anything that changed between macOS 14, 15, and 26.

## R1 — Paste into the frontmost app after a non-activating panel dismisses

**Prompt**

> How do open-source macOS clipboard managers (Maccy, Clipy, Pasteboard-style tools) and
> Raycast-like launchers paste the selected item into the app that was frontmost before the
> launcher opened? Compare: (a) posting ⌘V with `CGEvent` (`kCGHIDEventTap` vs
> `kCGSessionEventTap`, `CGEventSource` state IDs, key-down/key-up ordering, flags);
> (b) writing the text through the Accessibility API (`AXUIElement` focused element,
> `kAXSelectedTextAttribute`); (c) `NSPasteboard` write + `NSApp.hide` timing. Cover:
> the Accessibility permission requirement (`AXIsProcessTrustedWithOptions`), what happens
> when Secure Input is on (password fields, `IsSecureEventInputEnabled`), which apps ignore
> synthetic events (Terminal alternate screen, Electron, Java), race conditions between
> `orderOut`/`resignKey` of an `NSPanel` and the target app regaining key window status,
> and how tools "paste and restore" the previous pasteboard contents afterwards.
> Give me a minimal Swift 6 snippet for the CGEvent approach with the correct delay strategy.

**Bring back** — the recommended approach, the delay/ordering rules, the Secure Input
check, and the list of apps known to ignore synthetic ⌘V.

## R4 — Secret detection heuristics for clipboard text

**Prompt**

> I want an on-device "likely secret" detector for short clipboard strings (≤32 KB) with
> very low false positives. Survey the regexes and entropy rules used by gitleaks,
> detect-secrets, trufflehog, and GitHub secret scanning for: AWS access keys, GitHub
> tokens (`ghp_`, `github_pat_`), OpenAI/Anthropic-style `sk-` keys, Slack tokens, JWTs,
> PEM private keys, Google API keys, Stripe keys, generic high-entropy strings, and credit
> card numbers (Luhn). Recommend a compact rule set (≤20 rules) ordered by precision, the
> Shannon-entropy threshold and minimum length that avoid flagging URLs and hashes, and
> how to unit-test it with adversarial inputs.

**Bring back** — the rule table (name, pattern, precision note) and the entropy threshold.

> run `VACUUM` or `incremental_vacuum` after clearing large BLOBs, and how to export/import
> as JSON plus an images folder without losing FTS consistency?
