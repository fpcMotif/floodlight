## What is indexed

Nanospot indexes filenames and directory names under your home directory
(`$HOME`) into a memory-mapped file at
`~/Library/Application Support/Nanospot/names.flix`.

- On launch, Nanospot maps the last saved `names.flix` immediately so file
  search works without waiting for a scan.
- With Full Disk Access, a background thread scans `$HOME` with
  `getattrlistbulk(2)` and swaps in the fresh index atomically once ready.
- If you grant Full Disk Access during the first-launch prompt, Nanospot starts a
  fresh scan immediately.

Nanospot scans applications in `/Applications`, `/Applications/Utilities`,
`/System/Applications`, `/System/Applications/Utilities`, and
`~/Applications` on launch.

## Exclusions

To keep the File Index small and fast, the directory walker skips:

- hidden files and directories (names beginning with `.`);
- `node_modules`, `DerivedData`, `__pycache__`, `Caches`, `target`, `build`,
  `.build`, and `Pods`;
- symbolic links (indexed as entries themselves, never traversed); and
- any folder deeper than 48 levels.

Search matches file and folder names (and relative paths when your query contains
`/`). Nanospot does not index file text contents or read `.gitignore` files.

## Refreshing the index

Each scan replaces `names.flix` atomically via a temporary sibling file and
rename, while failed scans keep the previous index intact. Quit and reopen
Nanospot if you want to trigger a background rescan immediately.
