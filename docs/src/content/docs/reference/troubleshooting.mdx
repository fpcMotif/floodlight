---
title: Troubleshooting
description: Fix missing files, permission prompts, paste issues, and shortcut conflicts.
---

## Shortcut does not open Nanospot

Nanospot registers <kbd>⌥ Space</kbd> for Search and <kbd>⌥ ⇧ C</kbd> for
Clipboard History. If another app already owns one of those shortcuts, quit or
rebind that app's global shortcut and relaunch Nanospot.

## Desktop, Downloads, or Documents files are missing

1. Open **System Settings → Privacy & Security → Full Disk Access**.
2. Confirm **Nanospot** (`/Applications/Nanospot.app`) is on in the list.
3. If you rebuilt or replaced the app and its code-signing identity changed,
   reset the TCC entry first:

   ```sh
   tccutil reset SystemPolicyAllFiles com.nanospot.app
   ```

4. Relaunch Nanospot. It opens the Full Disk Access card so you can drag
   `/Applications/Nanospot.app` back into the list and rebuild `names.flix`.

## Return in Clipboard History copies instead of pasting

Direct paste sends <kbd>⌘ V</kbd> to the previous app using macOS Accessibility.
Enable **Nanospot** under **System Settings → Privacy & Security → Accessibility**,
then retry. Secure password fields still block simulated <kbd>⌘ V</kbd> input by
macOS design.

## An application or newly created file is missing

- Nanospot scans standard `.app` bundles under `/Applications` and
  `~/Applications` on launch.
- Protected or newly added folders appear once Full Disk Access allows access
  and the background scan of `$HOME` completes. Relaunch Nanospot to run a
  fresh scan.

## The app cannot be opened

Download the latest `Nanospot.dmg`, drag **Nanospot** to `/Applications`, and
open that copy instead of running from the mounted disk image or Downloads.
