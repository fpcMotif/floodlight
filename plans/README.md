# Implementation Plans

Generated by the improve skill against commit `64cc313`: plans 001–005 on
2026-11-10, plans 006–015 on 2026-11-17 from an audit of speed and memory in
the Zig frontend. Each executor: read the plan fully before starting, honor
its STOP conditions, and update your row when done.

The working tree had uncommitted changes when these plans were written,
including in most files under `frontends/nanoui/src/`. Plans 002, 003 and
006–015 quote those files from the working tree, not from the commit. Their
drift checks say how to confirm each excerpt.

## Measured baseline for plans 006–015

Taken on 2026-11-17 on Apple silicon, release build, before any change.

| Measure | Value |
|---|---|
| Keystroke to ranked rows, 200 apps, no files, no frame | p50 1.79 µs, p99 6.58 µs |
| Hot key to restored session, frame not timed | p50 0.46 µs, p99 3.92 µs |
| Return to action, no store | p50 0.71 µs, p99 5.38 µs |
| Hidden footprint, `make bench-nanoui-memory`, 3 cycles | 58.8, 59.0, 62.8 MB (budget 60, fails) |
| Hidden footprint, sampled 2 s later with `vmmap` | 45.8 MB |
| Open footprint | 181–194 MB, 97 MB of it graphics |
| Hidden heap traced to the UI library | at least 11 MB of about 23 MB |

The three latency numbers come from a benchmark that skips file search, the
store and the frame build. Plan 006 adds the missing measurements. A hidden
footprint near 30 MB is a realistic target; an AppKit process with one
window costs 10–15 MB before the app allocates anything.

## Decisions

- **Web suggestions default** (plan 002): the maintainer decided on 2026-11-10
  that suggestions stay on by default. The plan adds a debounce, a minimum
  length, and README disclosure, and does not change the default.
- **Plan selection for 006–015**: the maintainer asked on 2026-11-17 for
  plans covering all ten findings of the speed and memory audit.

## Open decisions

- **What the file index contains**: the scan skips dot-names and eight
  folder names (`core/src/scan.zig`, `keep` and `pruned`). It indexes
  `~/Library` and the insides of packages such as `.app` and
  `.photoslibrary`. Skipping them would shrink the index and the work per
  keystroke, and would stop Floodlight finding files there. No plan changes
  this until the maintainer decides. Plan 009 only stops bundle contents
  from using result slots.

## Findings considered and rejected

These were verified by reading the code and judged not worth a plan now.

- **Zig file index can hang on a corrupt file**: refuted. `relativePath`
  consumes at least one byte of its buffer per parent hop after the first
  (`core/src/index.zig:78-82`), so a parent cycle ends within 4,096 iterations.
- **Zig file index hardening** (no `fsync` before rename at
  `core/src/index.zig:173-183`; `parse` validates section ranges only at
  `:257-280`; one-byte write past `PathCache.buf` at `core/src/search.zig:177`
  for a directory path of exactly 4,096 bytes): real but low impact. A torn
  file needs power loss, not a process crash. Worth a small hardening change
  later, not a plan now.
- **A 100x faster search and 1% of current memory**: not reachable. The
  benchmarked search path already runs in microseconds, and a hidden AppKit
  process costs 10–15 MB before the app allocates anything. The plans target
  the unmeasured frame build and a hidden footprint near 30 MB.
- **SQLite connection settings** (`frontends/nanoui/src/clipboard.zig`, the
  `schema` pragmas: no `cache_size`, `temp_store` or `journal_size_limit`):
  the page cache holds about 2 MB at most. Not worth a plan.
- **Thumbnail column sits before columns added later** (`clipboard.zig`,
  `columns_added_since_first_schema`): the cost of reading past the blob is
  unmeasured and would need a table rebuild. Plan 010 removes the thumbnail
  from the hot query, which removes most of the concern.
- **One statement per picture file at launch** (`clipboard.zig`,
  `clearStrayFiles`): about 0.1 s at 5,000 files, once per launch.
- **The C API skips the `FileIndex` lifecycle** (`core/src/c_api.zig`):
  nothing links the C API today.
- **The index builder grows its lists by doubling** (`core/src/index.zig`,
  `Builder`): a short-lived peak during a rescan only.
- **Filter chip counts scan the rows several times per build**
  (`frontends/nanoui/src/list.zig`, `count`): tens of microseconds. Noted in
  plan 008.
- **The display link runs at full rate while the panel is open**
  (`frontends/nanoui/src/mac.zig`, `keepLinkAtDisplayRate`): deliberate
  workaround for a stale-frame bug in nanoui 0.9.2. Revisit on a nanoui
  upgrade. Noted in plan 015.
- **The clipboard poll wakes the app twice a second** (`main.zig`,
  `captureTick`): macOS has no pasteboard change notification, and an idle
  tick is one integer compare.
- **The index is rebuilt only at launch and on the Full Disk Access grant**
  (`main.zig`, callers of `rebuildIndex`): a freshness gap, not a speed
  problem. `docs/adr/0010-zig-file-index-core.md` lists live updates as a
  known gap. A rate-limited rebuild on panel show is a small feature for the
  maintainer to weigh.
- **Capture starts before onboarding consent**
  (`Sources/Floodlight/App/AppDelegate.swift:49-50`): this is an opt-out
  default, not a bypass. Product decision, noted in plan 004.
- **Image preview temp files never removed**
  (`Sources/Floodlight/Search/ClipboardSearch.swift:271-288`): confirmed, low
  impact; files are created only on an explicit Quick Look. Noted in plan 001.
- **Release workflow has no check or test gate**
  (`.github/workflows/release.yml`): confirmed, but `.github/workflows/ci.yml:8-9`
  states the decoupling from lint policy is deliberate. Adding `make test` and
  an ancestor-of-`main` check before signing is a small optional change.
- **Clipboard database is plaintext with mode 0644**: true, low impact. The
  parent folder `~/Library/Application Support` is mode 0700.
- **No size budget in the Swift clipboard store**: confirmed (465 MB of PNG in
  872 images on one machine). Product decision, noted in plan 001.
